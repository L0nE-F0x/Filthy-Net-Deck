# Audit — v2.7.3 (2026-08-10)

Performance + correctness review of everything that landed over the weekend of
**2026-08-08 → 08-10** (v2.7.0 → v2.7.3, built with Kimi K3 and Grok 4.5).
Trigger: owner reported the app felt slower and less usable after that work,
not better.

Scope: `ed88bae..HEAD` for `src/`, `src-tauri/src/`, `pipeline/`.
Everything below was verified, not inferred — measurements are from a
production Vite build served locally, not the dev server.

---

## Verdict

The weekend fixed real things (the splash re-render loop was a genuine
900 ms-interval bug, and destroying idle WebView2 renderers is a real RAM win).
But three of the "performance" changes were net negative, and one reintroduced a
Windows deadlock this repo had already been bitten by and documented.

| # | Severity | Area | Issue |
|---|----------|------|-------|
| 1 | **P0** | Rust | Webview built inside `run_on_main_thread` → Windows event-loop deadlock |
| 2 | **P0** | Rust | Tray-hint toast builds its webview from the event-loop thread |
| 3 | **P1** | React | Page-level `lazy()` guaranteed a skeleton flash on every page's first visit, for zero saved bytes |
| 4 | **P1** | React | ⌘K rebuilt the whole card index on every open |
| 5 | **P1** | CSS | Page-transition animation silently dead (`.content-enter` matched nothing) |
| 6 | **P1** | Store | Tracker poll skipped updates it should have applied |
| 7 | **P2** | Store | `startTransition` around Zustand `set` — a no-op that documented a falsehood |
| 8 | **P2** | Sets | Offline set galleries had no fallback after the cache started stripping them |
| 9 | **P2** | CSS | `contain-intrinsic-size` undershot real card height by 31 px |

## 1 · P0 — `arena.rs` rebuilt the documented deadlock

```rust
// v2.7.1, src-tauri/src/arena.rs
let _ = app.run_on_main_thread(move || {
    if running {
        crate::presence::show(&handle);          // → ensure_window → build()
        crate::overlay::prewarm_if_enabled(&handle); // → ensure_window → build()
    }
});
```

`WebviewWindowBuilder::build()` called from inside a `run_on_main_thread`
callback **deadlocks the event loop on Windows**: the window is created but
`build()` never returns, and every later main-thread task is wedged behind it —
including the tray menu's `app.exit(0)`. This is the exact failure documented in
`toast.rs`'s own comments and in `handoff.md` ("Creating WebView windows
**inside** `run_on_main_thread` on Windows can **deadlock**"), found originally
on 2026-07-22.

The trigger is *Arena launching* (or already running at app start), so it
presents as "the app randomly stops responding to the tray while I'm playing" —
which is roughly how the regression was reported.

**Fixed:** create from the poll thread (Tauri does its own hop internally);
keep only teardown on the main-thread hop. Matches `toast::show_toast` and
`tracker.rs`'s `overlay::show`, which were always correct.

## 2 · P0 — the tray hint inherited the same hazard

`notify_tray_hint_once()` runs from the `CloseRequested` window event (the event
loop) and from the `main_window_hide_to_tray` command, then calls
`toast::show_toast` → `ensure_window` → `build()`.

This was *previously safe by accident*: `toast::prewarm` at boot meant the
window already existed, so `ensure_window` early-returned. v2.7.1 removed the
prewarm (correctly — it held a renderer all day) without noticing that
`notify_tray_hint_once` depended on it. The first close-to-tray on a fresh
install now builds the toast webview from the event loop.

**Fixed:** the hint's toast is raised on its own thread.

Note the prewarm removal itself is right and should stay — see
`docs/MAINTENANCE.md`.

## 3 · P1 — page-level code splitting cost more than it saved

v2.7.2 put all 11 pages behind `React.lazy` + `Suspense`, then prefetched every
chunk on an idle callback. Measured on a production build:

- all page chunks were downloaded **~1.2 s after boot**, before any interaction;
- yet **every first visit to a page still flashed the skeleton**.

`React.lazy` renders its fallback once before resolving even when the module is
already in cache. So the split deferred nothing (idle prefetch pulled it all
anyway) and bought a guaranteed flash on first visit to each page, permanently.
Adding `startTransition` (item 7) could not suppress it either.

**Fixed:** pages are static imports again. The split that *does* pay — `main.tsx`
lazy-loading App vs. the overlay / toast / presence roots — is kept, so the three
secondary WebView2 renderers still never parse the main app.

| | before fix | after fix |
|---|---|---|
| nav click → painted page | skeleton, then content | **0–2 ms, synchronous** |
| skeleton flash on first visit | every page | none |
| JS requests at boot | 17+ | 5 |
| overlay/toast/presence payload | unchanged | unchanged (split preserved) |

## 4 · P1 — ⌘K re-indexed the feed on every open

`useMemo(() => open && meta ? buildCardIndex(meta) : null, [open, meta])` — the
`open` dependency means the index is discarded on close and **rebuilt on every
single open**, walking every decklist before the palette can paint. The v2.7.2
note ("index only while open") describes a fix for eager indexing but introduced
per-open rebuilding.

**Fixed:** lazy *and* cached, keyed on the meta object — built at most once per
meta refresh. Palette open is now 0.1–0.3 ms.

## 5 · P1 — the page transition was silently dropped

`.content { animation: pageIn … }` was renamed to `.content-enter`, but nothing
ever applies that class — `<main>` is `className="content"`. Dead rule; the
fade was simply gone.

**Fixed:** the fade is restarted from an effect on `page` change, which restores
the animation *without* reintroducing the `key={page}` remount that v2.7.2
correctly removed.

## 6 · P1 — the tracker poll dropped real changes

The new "skip `set()` when nothing changed" guard compared only `length` plus
the **first and last** match. Matches are edited in place — opponent tags, deck
reassignment, corrected results — so any mid-list edit at unchanged length read
as "no change" and never reached the UI.

**Fixed:** `sameMatchList()` compares every match shallowly (with a JSON
fallback for the nested game/rank objects). Still cheap; still skips the
no-op 12 s polls, which was the valid part of the idea.

## 7 · P2 — `startTransition` around Zustand `set`

12 store actions were wrapped in `startTransition` with the comment "so the nav
highlight can paint before the heavy page tree mounts". Zustand reaches React
through `useSyncExternalStore`, and **React always renders external-store
updates synchronously** — the wrapper deferred nothing. Removed, with a comment
saying why so it does not come back.

## 8 · P2 — offline set galleries had no floor

`slimForCache()` (correctly) stops storing full `cards[]` for live/released sets
in `localStorage`, and `fetchSetGallery()` fetches `meta/sets/<code>.json` from
the CDN. But in production the CDN was the *only* source, so with no network
there was nothing to fall back on — even though the JSON ships inside the app
bundle.

**Fixed:** CDN origins first (the bundled copy is frozen at build time), then
the bundled path as an offline floor.

## 9 · P2 — measured the deck-card placeholder

`contain-intrinsic-size: auto 160px` against a real rendered card of **191 px**.
`auto` means it self-corrects after first render, so this only affected the cold
pass, but the guess made the scrollbar jump. Set to the measured value.
